# Безопасность

## Поддерживаемая версия

Исправления безопасности выпускаются для текущего состояния ветки `main`.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в обычном issue. Используйте приватное сообщение об уязвимости в разделе Security репозитория. В сообщении укажите затронутую версию, сценарий воспроизведения, возможные последствия и, если возможно, безопасный пример запроса.

Авторы подтвердят получение сообщения, проверят воспроизведение и согласуют срок раскрытия. Секреты, реальные пользовательские фотографии и персональные данные не должны входить в отчёт.

## Границы доверия

- загруженные изображения считаются недоверенными и проверяются декодером, размером и разрешением;
- ссылки на фотографии подписываются отдельно для чтения и удаления и имеют ограниченный срок действия;
- API, PostgreSQL, Kafka и ksqlDB не должны публиковаться в интернет напрямую — внешний доступ идёт только через HTTPS reverse proxy;
- ключи, пароли и токены задаются только через production environment file или секреты платформы;
- результат модели является предварительной оценкой и не должен использоваться как медицинский, ветеринарный или агрономический диагноз.
