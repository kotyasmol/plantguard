# Хранилище фотографий

На текущем этапе фотография сохраняется как самостоятельный объект. Связь с растением, наблюдением и записью `photos` будет создана на следующем этапе вместе с API истории.

## Сценарий

1. `POST /api/v1/photos` принимает один файл.
2. API ограничивает объём входного потока до настроенного размера.
3. Pillow декодирует изображение и сверяет реальный формат с `Content-Type`.
4. Проверяются число пикселей и отсутствие анимации.
5. Файл атомарно записывается под случайным ключом вне PostgreSQL.
6. Клиент получает SHA-256, размеры и короткоживущие ссылки для чтения и удаления.
7. `GET` и `DELETE` проверяют срок действия и HMAC-подпись, привязанную к HTTP-методу и ключу объекта.

Поддерживаются JPEG, PNG и WebP. Исходное имя не используется как путь хранения.

## Локальный адаптер

В Docker Compose файлы находятся в отдельном томе `photo-data`. `make down` сохраняет его, а `docker compose down --volumes` удаляет вместе с остальными локальными данными проекта.

Ключ имеет вид `aa/bb/<uuid>.<extension>`. Компоненты пути, абсолютные пути, обратные слеши и выход за корневой каталог отклоняются. Запись выполняется через временный файл и атомарное перемещение.

## Настройки

| Переменная | Назначение | Значение разработки |
| --- | --- | --- |
| `PLANTGUARD_MAX_IMAGE_BYTES` | Максимальный размер файла | 10 МиБ |
| `PLANTGUARD_MAX_IMAGE_PIXELS` | Максимальное количество пикселей | 25 млн |
| `PLANTGUARD_PHOTO_STORAGE_PATH` | Корень файлового хранилища | `.data/photos` |
| `PLANTGUARD_PHOTO_URL_TTL_SECONDS` | Срок действия ссылки | 900 секунд |
| `PLANTGUARD_PHOTO_SIGNING_KEY` | Ключ подписи ссылок | Только локальное значение |

При `PLANTGUARD_ENV=production` запуск с демонстрационным ключом подписи запрещён. Настоящий ключ должен передаваться серверу через хранилище секретов и не коммититься.

## Развёртывание

Интерфейс `PhotoStorage` отделён от локальной файловой системы. Для одного выделенного сервера можно оставить постоянный том с резервным копированием. При горизонтальном масштабировании адаптер следует заменить на S3-совместимое хранилище, не меняя обработчики API.
