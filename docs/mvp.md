# Объём первой версии PlantGuard

Статус: проектный объём зафиксирован для разработки; формулировка темы и трактовка `re` ожидают подтверждения преподавателя.

## Цель

Помочь владельцу комнатного растения заметить изменения его состояния и выбрать безопасный следующий шаг. Первая версия поддерживает распознавание ограниченного набора видов, выделение видимых признаков, учёт описания и истории ухода, повторное наблюдение и объяснимую оценку. Вывод системы — поддержка решения, а не подтверждённый диагноз заболевания.

## Поддерживаемые виды

| Код вида | Название в интерфейсе | Граница распознавания |
| --- | --- | --- |
| `monstera_deliciosa` | Монстера деликатесная (*Monstera deliciosa*) | Молодые и взрослые листья должны присутствовать в проверочной выборке. |
| `epipremnum_aureum` | Эпипремнум золотистый (*Epipremnum aureum*) | Естественная пестролистность не должна считаться повреждением. |
| `ficus_elastica` | Фикус каучуконосный (*Ficus elastica*) | Сортовые различия не должны автоматически трактоваться как заболевание. |

Выбор этих трёх видов — ограничение объёма, а не утверждение о доступности готового датасета. На этапе подготовки данных потребуется проверить права использования изображений и достаточность примеров каждого вида. Если проверка не пройдёт, состав видов пересматривается до обучения модели.

Для любого другого вида предусмотрен ответ «не распознано» и ручной ввод названия. Система не подменяет неизвестный вид ближайшим из трёх поддерживаемых.

## Наблюдаемые признаки

На снимке выбранного листа первая версия ищет:

1. пожелтение;
2. пятна или локальное потемнение;
3. видимое повреждение ткани — сухие края, разрывы или отверстия.

Возможны также ответы «признак не обнаружен» и «по этому снимку оценить нельзя». Список описывает внешний вид, а не причину. Например, жёлтый участок может быть особенностью сорта, следствием условий содержания, вредителей или болезни; из одного снимка нельзя надёжно выбрать одну причину. Это ограничение согласуется с материалами [University of Maryland Extension](https://extension.umd.edu/resource/yellowing-leaves-indoor-plants) и [Illinois Extension](https://extension.illinois.edu/houseplants/troubleshooting).

## Входные данные и сценарий

Пользователь добавляет фото растения, краткое описание симптомов и, при желании, дату последнего полива, пересадки или перестановки. Температура и относительная влажность **воздуха** принимаются как необязательные показатели с единицами измерения и источником данных. Влажность почвы не выводится из влажности воздуха: она будет поддерживаться только при отдельном ручном вводе или сенсоре с известным способом измерения.

Основной сценарий:

1. Создать карточку по фотографии; получить не более трёх кандидатов вида.
2. Подтвердить вид, исправить его вручную или оставить неопределённым.
3. Добавить описание и доступные сведения об уходе.
4. Получить список видимых признаков, возможные объяснения и безопасные следующие действия.
5. Записать выполненное действие по уходу.
6. Позднее сфотографировать тот же лист, используя подсказку для совмещения кадра.
7. При сопоставимых снимках увидеть изменение признаков и временную шкалу событий; иначе получить просьбу повторить фото.

Изменение состояния после действия показывается как последовательность событий. Причинно-следственная связь без дополнительных данных не утверждается.

## Границы рекомендаций

Разрешены проверочные действия: уточнить вид, повторить снимок, осмотреть нижнюю сторону листа, проверить влажность субстрата и дренаж, отметить фактический полив или изменение освещения, наблюдать динамику. Рекомендация должна ссылаться на конкретные признаки и входные данные.

Первая версия не назначает пестициды, фунгициды, удобрения или дозировки; не утверждает наличие конкретного патогена только по общим признакам; не даёт безусловной команды полить, пересадить или изолировать растение при нехватке данных. Если признаки противоречивы или вид не подтверждён, система сообщает о неопределённости и запрашивает уточнение.

Текущие числовые пороги в модуле принятия решений являются техническими заглушками. Их нельзя считать ботаническими нормами для всех трёх видов; пересмотр правил входит в отдельный этап плана.

## Измеримые критерии приёмки

Ниже заданы **целевые пороги для первой версии**, а не достигнутые результаты. Метрики считаются на отложенных данных, не использованных для обучения или подбора порогов. Снимки одного растения и почти одинаковые кадры не должны попадать одновременно в обучение и проверку.

| Область | Критерий |
| --- | --- |
| Распознавание вида | Macro-F1 не ниже 0,85 на трёх поддерживаемых видах; не меньше 50 независимых проверочных фото каждого вида. |
| Неизвестные виды | Не меньше 90% фото неподдерживаемых видов получают ответ «не распознано»; проверочная выборка — не меньше 50 фото. |
| Уверенность модели | Проценты уверенности показываются пользователю только после проверки калибровки; целевой ECE не выше 0,10. |
| Визуальные признаки | Для каждого включённого признака precision и recall не ниже 0,80; не меньше 40 положительных и 40 отрицательных проверочных примеров. Признак без достаточной выборки не включается в релиз. |
| Анализ текста | Macro-F1 извлечения поддерживаемых фактов не ниже 0,85 на минимум 100 вручную размеченных русскоязычных описаниях. |
| Сопоставимость снимков | Не меньше 95% заранее размеченных несопоставимых пар отклоняются; проверочная выборка — не меньше 50 таких пар. |
| Динамика признаков | Оценка «улучшилось / без заметного изменения / ухудшилось» совпадает с разметкой экспертов минимум в 80% сопоставимых пар; минимум 50 проверочных пар. |
| Безопасность вывода | В фиксированном наборе не меньше 100 сценариев нет рекомендации, не опирающейся на данные или разрешённый каталог действий. Недоступность модели приводит к безопасному ответу без выдуманного диагноза. |
| Сквозной сценарий | Автоматический тест проходит путь от создания растения до повторного наблюдения и сравнения; данные сохраняются после перезапуска сервисов. |

Критерии могут быть пересмотрены только явно и до оценки на финальной тестовой выборке. Если нужной разметки не удастся собрать, соответствующая возможность исключается из релиза, а не объявляется проверенной.

## За пределами первой версии

- точная диагностика конкретных грибковых, бактериальных и вирусных заболеваний;
- гарантированная оценка любых комнатных растений;
- автоматическое лечение без подтверждения пользователя;
- собственные аппаратные датчики и управление теплицей;
- социальная сеть, каталог товаров и торговая площадка.

## Вопросы для согласования

1. Что означает `re` в записи требования «Data mining — re, LLM»? До ответа оно не считается реализованным или согласованным. Если имелись в виду регулярные выражения, их можно применить к нормализации описаний симптомов и показателей.
2. Принимается ли ограничение первой версии: диагностика состояния и вероятных причин без утверждения конкретного заболевания? Для диагностики отдельных болезней потребуется согласовать перечень болезней, источник размеченных данных и отдельные критерии качества.

Ботанические названия проверены по [Plants of the World Online: *Monstera deliciosa*](https://powo.science.kew.org/taxon/87478-1), [*Epipremnum aureum*](https://powo.science.kew.org/taxon/87014-1) и [*Ficus elastica*](https://powo.science.kew.org/taxon/60458499-2).
