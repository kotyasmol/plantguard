# Приватность и ограничения

PlantGuard хранит адрес электронной почты, отображаемое имя, фотографии растений, текст наблюдений, показатели среды и историю ухода. Эти данные используются только для работы карточек растений и расчёта оценки состояния.

## Хранение

- метаданные и история находятся в PostgreSQL;
- фотографии находятся в отдельном Docker volume и не включаются в Kafka;
- в Kafka передаются идентификаторы, ссылки-хранилища и структурированные события;
- bearer-токен профиля хранится в браузере пользователя; в базе находится только его хеш;
- при удалении профиля удаляются связанные записи и файлы фотографий.

Если настроен `PLANTGUARD_PLANTNET_API_KEY`, фотография также передаётся во внешний Pl@ntNet Identification API для определения вида. Без ключа внешняя передача не выполняется. Оператор публичного экземпляра обязан явно сообщить пользователю о включённом внешнем распознавании и учитывать политику обработки данных поставщика.

Оператор развёрнутого экземпляра определяет срок хранения резервных копий и обязан защищать production environment file правами `600`. Для публичной эксплуатации до регистрации реальных пользователей необходимо опубликовать политику обработки персональных данных, соответствующую применимому законодательству.

## Ограничения моделей

Встроенный классификатор поддерживает ограниченный набор комнатных растений и не проходит целевые релизные метрики. Опциональный Pl@ntNet-адаптер расширяет покрытие, но остаётся вероятностным внешним сервисом и также требует подтверждения пользователя. Анализ состояния определяет только наблюдаемые признаки: пожелтение, тёмные области, повреждение ткани, опадение и увядание. Он не устанавливает заболевание и не назначает химическую обработку.

Рекомендации являются предварительными и должны проверяться пользователем. При низкой уверенности, конфликте сигналов или неподходящей фотографии система запрашивает дополнительное наблюдение. Для ценных, токсичных или быстро ухудшающихся растений следует обратиться к профильному специалисту.
