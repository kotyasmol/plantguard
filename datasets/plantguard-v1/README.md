# PlantGuard v1 image registry

`manifest.jsonl` фиксирует изображения для разработки и независимой проверки первого классификатора видов. Сами файлы не копируются в Git: каждая запись содержит ссылку на исходное наблюдение iNaturalist, автора, лицензию фотографии, исходные размеры и стабильный идентификатор медиа.

В реестр включаются только исследовательские наблюдения с фотографиями под CC0, CC BY или CC BY-SA. Эти лицензии допускают повторное использование, в том числе в коммерческом проекте, при соблюдении условий атрибуции и ShareAlike. Лицензия наблюдения и лицензия фотографии различаются; скрипт проверяет именно `photo.license_code`.

Поддерживаемые классы:

- `monstera_deliciosa`;
- `epipremnum_aureum`;
- `ficus_elastica`;
- `unknown` — два неподдерживаемых вида для проверки отказа от уверенного ответа.

Для каждого класса зафиксировано 60 изображений для обучения, 14 для настройки и 50 для независимой проверки. Одно наблюдение считается одним физическим экземпляром и не может попасть в разные части выборки.

Проверить реестр и заново получить отчёт:

```bash
make dataset-audit
```

Пересобрать реестр из публичного API iNaturalist:

```bash
.venv/bin/python scripts/build_dataset_manifest.py
```

Пересборка является осознанной операцией: опубликованные наблюдения и лицензии могут измениться. Поэтому обновлённый manifest и отчёт следует проверять в diff и фиксировать вместе. Перед обучением изображения необходимо скачать в игнорируемый каталог `.data/dataset-images`, проверить доступность ссылок и провести ручной контроль ошибочной разметки.

## Baseline распознавания

Команда `make train-species-model` скачивает изображения в игнорируемый каталог `.data`, обучает k-NN на визуальных дескрипторах, подбирает порог отказа только на validation-части и один раз оценивает модель на test-части. Артефакт включается в Python-пакет, а измерения сохраняются в `identification-report.json`.

Первая измеренная версия является инженерным baseline, а не готовой моделью: её Macro-F1 и полнота unknown-класса ниже целевых порогов. Отчёт намеренно фиксирует этот отрицательный результат; проценты baseline нельзя представлять пользователю как откалиброванную вероятность.

`visual-baseline-report.json` отдельно фиксирует регрессионную проверку пожелтения, локального потемнения и внутренних повреждений ткани. Она построена на синтетических контрольных изображениях и проверяет воспроизводимость правил, но не заменяет оценку на вручную размеченных реальных фотографиях.
